# iGPSPORT Web Studio

**iGPSPORT 码表定制工坊 · 非官方 iGPSPORT 码表页面编辑与预览工具**

面向 iGPSPORT 多款码表的 Web 页面编辑与预览工具，支持版式调整、数据字段配置、本地方案管理，以及 BSC500 实验性 Web Bluetooth 页面同步。项目同时保留 BSC500 V1.04.003 固件分析、V1.08.005 蓝牙抓包、RSC 解包工具、设置表解析器与地图底色离线验证，为后续定制能力提供研究依据。

本项目为非官方工具，与 iGPSPORT 官方无隶属关系。

[开发计划](DEVELOPMENT_PLAN.md)：Web 页面设置与真机同步 → 固件能力挖掘 → 类 Connect IQ 的自定义表盘／数据页设计平台。

## 网页设置工作台

[桌面数据页编辑器](web/index.html) 采用橙红色、浅灰背景和三栏工作区：左侧选择机型与管理页面，中间等比预览，右侧修改版式与数据项目。支持 BSC500、iGS800、BiNavi、BiNavi Air、BiNavi Ultra、iGS630S 和 BSC200 Pro；新增机型仅支持离线展示与编辑，不开放蓝牙读写。网页无构建和运行时安装依赖，不上传文件，也不需要官方账号。

在项目根目录启动本地服务器：

```bash
python3 -I -m http.server 8765 --bind 127.0.0.1 --directory web
```

使用桌面 Chrome 或 Edge 打开 **http://127.0.0.1:8765/**。离线设计可直接打开 HTML；蓝牙必须使用 localhost 或 HTTPS，Safari / Firefox 不支持此处使用的 Web Bluetooth。

### 桌面编辑与实验性同步

- **原厂版式编辑**：使用 Android 国内版 8.11.00 目录中的 76 种版式（普通数据页 1–12 项与专项页），按 `page_mode`、`line_width` 的真实行数、列数和行高权重预览。不将任意网页样式当作固件能力。
- **桌面操作**：点选屏幕数据格或右侧列表修改项目，搜索中文、英文或十六进制 ID，拖动交换字段、调整页面顺序。字段可用上下按钮排序，页面可用 `Alt + ↑/↓` 排序。支持撤销／重做、启用已有页面槽位和主页设置。
- **机型独立预览**：布局取自国内版 8.11.00 APK。iGS800 与 BiNavi 系列各有 22 种普通版式、54 种专项版式，分别保留 iGS800 的 5／7／9 项差异及 BiNavi 的爬坡差异；iGS630S 提供 15 种普通版式，该版 APK 的专项布局方法返回空列表；BSC200 Pro 提供 15 种普通版式及海拔、地图、骑行台、训练课程共 12 种专项版式。五行机型最多 10 项，其余最多 12 项。各机型的外框尺寸、屏幕内容区尺寸及定位取自 App 的 dp 参数，不是真机分辨率；BSC500 也改按 APK 的 198×295 内容区预览。外壳不再用 CSS 仿画或共享占位图：七款机型分别使用官方设备目录 `BACKGROUND_IN_PAGE_SETTING` 对应的独立 PNG，按原生 `FIT_CENTER` 缩放、水平居中与顶部偏移叠加内容。图片于 2026-11-27 经授权读取目录后保存为本地静态素材，逐项记录公开来源 URL、原图尺寸和 SHA-256；目录以 `devAppVer=0` 查询基础版本，BSC500 另以真机固件编码 `108005` 复核，图片 URL 一致。其他机型尚未核对特定固件版本，官方目录后续也可能更新。网页不包含登录功能、凭证或认证请求，正常预览不访问官方接口。图形仍借用公共原厂素材，新增机型的字段、固件显示及蓝牙均未验证。App 远程配置可能覆盖内置目录。
- **本地草稿**：按机型与模式分别自动保存，支持 JSON 导入导出，拒绝跨机型导入。切换机型会断开已有蓝牙连接并清除可写基线；原有 BSC500 草稿与方案仍可读取。页面名称和深浅色仅用于本地管理和预览，不写入设备。地图和读数都是示例；其他专项页以原生内容区占位，不假装精确模拟固件绘制。
- **图形字段预览**：心率分布、速度仪表、功率、曲线等 21 种已知图形字段改用国内版 8.11.00 APK 的原厂图片，共 84 张四种尺寸素材（`1x2` 全宽单行、`2x1` 半宽两行、`2x2` 全宽两行、`3x2` 全宽三行），按格子尺寸等比显示，不再统一显示数字占位。素材保留原色（深色模式也不反色），只是固定示例图，不含实时读数，也不代表字段已通过真机验证；新版 App 的远程素材与固件绘制可能不同。素材位于 `web/assets/igpsport-cn-8.11.00/field-previews/`，来自 APK 同名 `mipmap/icon_*_bg1` 资源。
- **图形显示位**：真机 16 个页面（含官方两次写入报文）的 `graphic_display` 与图形字段位置逐一吻合——普通数据页的第 i 位对应第 i 个字段是否按图形绘制。网页按此规则决定哪一格显示图形，并在字段或版式变化时重算该位；1 行 1 列放不下图形时按 APK 规则改为显示基础指标读数（速度／踏频／心率／功率）。专项页的该字段语义尚未确认，保留设备原值不改写。
- **字段证据**：185 个 App 字段中，47 个有 BSC500 固件模板或代码引用。默认隐藏未引用的候选项，可显式展开；静态引用不等于逐项真机确认。
- **蓝牙同步**：先断开手机 App，连接 BSC500，读取目标模式后编辑。同步需手动确认，依次执行重新读取并检查外部修改、下载原始配置备份、本机留存最近五份、写入、设备回执与读回核对。只有读回一致才标记同步成功；失败不自动重试。备份也可在「调试信息」中重新下载。
- **蓝牙诊断日志**：在「调试信息 → 蓝牙诊断日志」查看服务／特征 UUID、通知订阅、每个分片的发送字节与浏览器写入结果、原始通知、完整帧匹配和超时计数。最近 400 条日志限量保存到当前浏览器，刷新不丢失，可导出或手动清空。原始报文可能含页面配置，仅本机保存，不上传；“浏览器写入完成”不代表设备已接受。旧版摘要不能追溯补全为原始收发日志。读取保留与原始 iPhone 抓包一致的 29 字节单包，但优先使用特征声明支持的 `writeValueWithResponse`（`ble-notify-init-v5`）获取 ATT 层确认／错误；配置写入仍保留无响应 20 字节分片。原始 HCI 抓包确认 iPhone 在链路加密成功后才发送配置命令，而 Web Bluetooth 无法报告当前加密状态，不能将“连接成功”当成“已加密”。若系统要求正常蓝牙配对，请在电脑和码表上确认；不重放 App 绑定／解绑命令，也不要求解除手机账号绑定。ATT 确认阶段最多 45 秒，完成后另计 12 秒应用层回复；通知早于写入 API 完成时仍等待传输结果。无响应特征保留兼容方式但会明确记录限制；错误不自动重试，完整配置写入流程仍待真机验证。
- **连接初始化对照**：原 iPhone 抓包会启用 CCCD `0x0013/0x0019/0x001F/0x0025`；本机系统 GATT 日志将其分别对应到 `9e/8e/7e/6e` 四个 NUS 服务，APK `initCharacteristic` 同样初始化四路通知。网页现按此订阅，仍仅通过 9e 发送页面命令；辅助通道只记录、不发送命令、不混入主通道解析。可选服务缺失或订阅失败不伪装为已启用；未确认的 3e 服务不处理。用户已反馈补齐此初始化后可连接；不据此宣称配置写入已完成验证。
- **原值保护**：保留未改动的页参数和未知字段、重复页面记录、原始图形显示位；不按索引去重，不修改受设备限制的启用状态。未编号空记录按已观察到的官方写入行为不发送。导入到已读取设备时，只合并明确允许的编辑项，不信任文件携带的未知原始报文。

**验证边界**：官方 iPhone App 与 V1.08.005 真机的页面读写、字段修改、成功回执已在抓包中确认；本网页的协议编码、浏览器交互及假 GATT 同步流程已回归测试，**用户已反馈网页可连接真实 BSC500，配置写入与读回仍待真机验证**。若设备需要官方配对／会话握手，连接或读取可能失败，不会猜测或绕过。模式 0 有实测抓包，其他模式仅按 APK 明确传输模式编号，仍需实机确认。写入显式携带模式编号（Android 第四代设备分支）；iPhone 模式 0 的写入抓包省略了该默认值。此差异已在协议测试中单独核对，不能据此宣称新网页已经过真机验证。

初次加载的方案只是示例，不允许直接写入设备。若先离线编辑，先导出方案，再读取设备并重新导入；仅合并设备存在且类型匹配的槽位。同步只修改当前模式的页面配置，不刷固件、不写 USB 设置库，也不提供自定义字体或任意坐标安装能力。

### 验证

协议与模型测试只需 Node.js：

```bash
node --test web/tests/protocol.test.js
```

浏览器回归使用 Playwright 与已安装的 Chrome。启动上述本地服务器后，设置 `PLAYWRIGHT_MODULE` 为隔离安装的 Playwright 模块路径，再运行 `node web/tests/browser.test.cjs`。测试在新建浏览器上下文注入假 GATT，不连接实体码表，覆盖桌面编辑、响应式、导入导出、同步成功、冲突、超时、拒绝、断连、读回不一致及备份失败。

`web/tests/fixtures/page-messages.json` 仅包含 2026-11-26 抓包中的页面配置请求、回复和回执，去掉了 HCI 时间戳、连接句柄、设备标识及其他服务数据。原始抓包仍留在被 Git 忽略的 `.local/`。

## 官方更新与恢复

1. 正常可开机时，先保存并同步骑行记录，保留关键设置截图。给码表充足电量，手机与码表靠近，并保持手机联网和蓝牙开启。
2. 打开 iGPSPORT App → 设备 → 固件更新。以 App 为这台设备提供的版本为准。说明书给出的蓝牙更新时间最长约 20 分钟。升级进行中保持连接，等 App 提示完成，再核对设备版本、数据页、地图和传感器。
3. 如果升级未完成但码表还能正常启动，在设备和 App 均已退出更新状态后，可按说明书正常重启，再通过 App 检查更新。如果持续循环重启、无法开机或无法连接 App，向官方售后索取适用于硬件版本和地区的有线恢复流程，并确认能否重装同版本以及需保留哪些数据。系统里的「重置」会恢复设置和骑行模式并保留历史，「删除并重置」会清除历史。两项的手册说明均涉及用户数据和设置，尚无重装固件的证据。

## 在本地修改地图背景

将自行取得的厂商升级包放在 `.local/firmware/BSC500-V1.04.003.rsc`。下面的命令需要 Python 3，最后一步使用 uv 安装 Unicorn 并模拟执行绘制代码。第一次解包时，目标目录须为新目录。

```bash
mkdir -p .local/firmware
python3 firmware/extract_rsc.py .local/firmware/BSC500-V1.04.003.rsc \
  --extract-to .local/firmware/unpacked

original=.local/firmware/unpacked/BSC500_APP.bin
edited=.local/firmware/BSC500_APP-D5E8D4.local.bin

python3 native/map_background.py patch "$original" "$edited" --color '#D5E8D4'
uv run --with unicorn==2.1.4 native/map_background.py verify \
  "$original" "$edited" --color '#D5E8D4'
```

`--color` 接受六位 RGB 值。默认修改经典地图浅色背景。脚本也支持 `--theme classic --appearance dark` 和 `--theme colorful --appearance light`。彩色地图深色分支直接返回零，目前只纳入验证。脚本核对原始镜像的 SHA-256，并要求输出文件名可用。

工作区已有解包结果时，可将 `original` 指向现有的 `BSC500_APP.bin`。原始包与解包文件的哈希见 [RSC 清单](firmware/BSC500-V1.04.003-manifest.json)。

## 地图绘制与验证

应用镜像以 `0x60000000` 为基址，使用 ARM Thumb 指令。地图画布在 `0x60258528` 调用底色选择器 `0x6014D954`，随后将 RGB888 转成 RGB565，并将颜色交给矩形填充后端。

示例将经典地图浅色底色从 `#F6F6F6` 改成 `#D5E8D4`。两条配色指令从镜像偏移 `0x14D960` 开始，文件有 5 个字节发生变化。[离线验证记录](native/map-background-verification.json) 包含原始与修改镜像的哈希、字节差异和四种状态下的填充参数。验证使用构造的图形上下文运行固件绘制代码，记录后端收到的矩形和颜色。尚未执行真机测试或生成可刷写的升级包。
